# Recipes

Worked examples of tailoring a fork (see `TAILOR.md`). None of them is built into the base. Each says what to ask the person, which spec rules to add, change or delete, where the code goes, and which tests prove it. Use them as patterns, not as scripts: the person's answers decide the details.

| Recipe | Kind of change |
|---|---|
| [gtd-keywords.md](gtd-keywords.md) | Flavour: values in `src/flavour.ts` |
| [date-id-journal.md](date-id-journal.md) | Flavour: a template, for an existing Emacs setup |
| [closed-on-done.md](closed-on-done.md) | Core: a change to an editing rule |
| [capture-datetree.md](capture-datetree.md) | Feature: changing what one feature does |
| [drop-a-feature.md](drop-a-feature.md) | Feature: removing one whole |
